4. AuthDB.ts — STORAGE, CRYPTO, OTP (BACKEND REPLACEMENT)
--------------------------------------------------------------------------------
Class: AuthDB (singleton, accessed as `authDB = AuthDB.getInstance()`)

localStorage keys:
- hts_auth_db_v4 ........ Main DB JSON {users, logins} (v4 fresh wiped on 2026-10-10)
- hts_current_user_v4 ... Current session user id (email key)
- hts_auth_schema = '4' . Schema version guard. If mismatch, wipes DB + session + login/signup detail logs.
- LEGACY keys deleted on boot: hts_auth_db_v3, hts_current_user_v3
- OTPs are IN-MEMORY only: private otps = Map<normalizedId, {code, expiresAt, purpose}>
  OTP_TTL = 5 * 60 * 1000 (5 min). 6-digit zero-padded from crypto.getRandomValues.

Security:
- PBKDF2_ITERATIONS = 210_000, hash SHA-256, derive 256 bits via crypto.subtle.
- Requires secure context (HTTPS or localhost), else throws
  "Secure password storage requires HTTPS or localhost."
- encode/decode = btoa/atob base64 for Uint8Array.
- verifyPassword uses constant-time XOR compare.
- findUser / listUsers STRIP passwordSalt/passwordHash before returning.

Key methods:
- loadFromStorage(): validates JSON with isRecord/isStoredUser guards, filters bad entries.
- persist(): JSON.stringify to hts_auth_db_v4
- findUserRecord(identifier): lookup by normalized email key OR contact match via
  normalizeContact (spaces/dashes/brackets ignored, case-insensitive).
  normalize = trim().toLowerCase()
- findUser(identifier): public user or null
- hasAccount(identifier): boolean
- listUsers(): public users array (for admin)
- listLoginEvents(): logins sorted desc by timestamp
- hashPassword(password, salt), verifyPassword(password, user) [private]
- startOTP(identifier, purpose): generates + stores code, returns code (caller displays it)
- verifyOTP(identifier, code, purpose): checks purpose+expiry+exact match, single-use (deletes).
  Deletes expired OTPs on failed check.
- createUser(details: SignupDetails):
  Validations via shared helpers: name>=3 chars, isValidContact, isValidEmail (see §10),
  password>=6, duplicate email OR contact -> throw "An account with this email or contact number already exists."
  Creates User with random 16-byte salt, PBKDF2 hash, loginCount 0.
- login(identifier, password): finds user, verifies password else throw
  "Email, contact number, or password is incorrect." On success: updates lastLoginAt,
  loginCount++, pushes {userId, timestamp}, keeps only last 100 logins, persists,
  sets hts_current_user_v4.
- resetPassword(identifier, password): NOT currently wired to UI flow (recovery OTP exists
  but no reset form yet). Validates len>=6, re-salts + re-hashes.
- getCurrentUser(): reads session key -> findUser
- logout(): removes session key (method exists; NO logout button in UI anymore —
  main screen was cleaned, so session can only be cleared via storage/schema bump).
- clearAll(): wipes DB + OTPs + logout (no UI calls this).

Important quirks:
- User.id = emailKey. Contact login works via scan, but session stores email id.
- Contact uniqueness is enforced via hasAccount(contactKey) scan.
- Logins array capped at 100, SignupDetails capped at 100, LoginDetails capped at 20.

10. VALIDATION RULES (SINGLE REFERENCE — shared helpers in index.ts)
--------------------------------------------------------------------------------
- normalizeContact(v): trim + strip spaces/dashes/dots/brackets, keeps leading +.
- isValidEmail(e): trim, len<=254, no spaces/.., single @, local<=64, valid chars,
  no leading/trailing dot, domain has dot, valid labels, TLD /^[A-Za-z]{2,}$/.
  Blocks a@b.c, abc@gmail, user@.com, test..mail@gmail.com, test@test.
  Allows test@gmail.com, x@y.co, TEST@GMAIL.COM.
- isValidContact(c): normalize, then /^\+?[0-9]{7,15}$/, rejects all-same-digit
  (0000000000), 10-digit without + must be /^[6-9][0-9]{9}$/ (blocks 1234567890),
  +91 12-digit must be 91+6-9+9 digits. Allows 9876543210, +919876543210,
  +91 98765 43210, +1 234567890.
- isValidIdentifier(v) = isValidEmail(v) || isValidContact(v)
- Used EVERYWHERE: AuthDB.createUser, AuthUI validateSignupStep/handleSignup/
  handleLogin/updateBotFromInput/handleReverify/sendOTP. AuthDB.findUserRecord
  compares contacts via normalizeContact (spaces/dashes ignored).
- Name: trim len >=3
- Password/secret: len >=6
- Confirm: === password
- Terms: must be checked
- OTP: /^\d{6}$/, 5-min TTL, single-use, purpose must match
- Email fit: paintMirror shrinks long emails to min scale .50 (passwords .72) so the
  full address fits the identifier box end-to-end.
